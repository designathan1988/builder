# Architecture

Every concept has one owner module. A second implementation of a concept that has an owner here is a defect; a new concept gets its line here, and its data in the manifest, in the same commit as its code. `manifest:check` rule `owner` fails when the owner of a command in `manifest/commands/*.json` differs from the table "Command owners" below.

Layers: `src/core/` is the document core in plain TypeScript (no React, no DOM); `src/editor/` is the React editor; `src/app/` wires the two; `src/manifest/` reads and checks the contract; `src/generated/` is written by `npm run gen` only; `tools/` runs in Node only.

## Concepts of foundation part 1

Each module below exists by the end of part 1; until a module lands, its line is the plan it follows.

| Concept | Owner | Responsibility | Never |

| Generated types and registries | `tools/gen/types.ts` | Writes `src/generated/` from the manifest and the catalogues: the id unions (CommandId, DoorId, PropertyId, ElementType, MessageId…), each command's argument types, the value lists the "generated" doors offer. | Hand edits in `src/generated/` (gen:check fails); logic in generated files. |

| Command registry and the "not available yet" marker | `src/core/commands/registry.ts` | The contract of the command table: its type `CommandTable` (a key for every CommandId), `registerHandler` (with the handler, optionally the command owner's `current`: whether a door with given arguments stands for the state the store holds, which `src/editor/doors/current.ts` asks), the `NOT_AVAILABLE_YET` marker, `registerPredicate` (with, optionally, the predicate's `refusal`: the message its failure shows, which the store accepts only when it is the command's `refusalKey` or one of its manifest `refusals`, so a refusal can name what it refuses), the handler's context and outcome; and the same contract for features: `FeatureTable` (a key for every FeatureId), `registerFeature`, `isRegistered`. | The command table | `src/app/commands.ts` | The one map from every command to its handler or `NOT_AVAILABLE_YET`, and the table of registered predicates; a missing or extra entry is a type error. | Handlers written inline; any other map of commands. |
| The feature table | `src/app/features.ts` | The one map from every feature of the manifest to `registerFeature(id)` (built) or `NOT_AVAILABLE_YET`, in the manifest's order, and `isFeatureBuilt`; a missing or extra entry is a type error (`FeatureTable` of the command registry). A feature is registered once every scenario of it runs and passes through every door it names: the scenario runner runs only registered features, and the census fails a registered feature with no scenario, a command it lists not built, or a scenario door that does not work yet. Plain data: the runner and the census read it in Node. | Deriving "built" from the commands (a feature is built when it is registered, never because its commands are); any other list of built features. |

| Validation | `src/core/document/validate.ts` | Whole-tree validation of a document and its selection against the model and the manifest, on every commit. | Store and dispatch | `src/core/store/store.ts` | The one store: document, selection, history, last message and the editor state; changes only through `dispatch(command)`; deep-freezes every state in development and tests. `canRun(command, args)` says whether a command would run now (built, its predicate holds, its handler does not refuse) and changes nothing: the context menu shows only what applies. `refusal(command, args)` says why not (not available yet, the predicate's refusal, the handler's), or null, and changes nothing either: a palette tile's creation drag draws the refusal its drop would meet. | Transactions | `src/core/history/transaction.ts` | Applies JSON patches, records their inverses, drops patches that change nothing; one transaction per dispatch or per gesture, with the selection before and after. | Touching the history stacks. |
| History | `src/core/history/history.ts` | The undo and redo stacks, coalescing, `history.undo` and `history.redo`: undo restores the document and the selection before the command, redo the ones after; no entry for a command that changes nothing. | Storing snapshots of editor state; entries for non-undoable commands. |
| Clock port | `src/core/ports/clock.ts` | The only reader of the time (`Date.now`); tests pass a fixed clock. | Being bypassed: a lint rule forbids `Date.now` and `new Date()` elsewhere. |
| IdGenerator port | `src/core/ports/ids.ts` | The only source of ids (`crypto.randomUUID`); tests pass a counter. | Being bypassed: a lint rule forbids `Math.random` and `crypto.randomUUID` elsewhere. |
| Layout port | `src/core/ports/layout.ts` | Where the canvas draws each node of the page it shows (`box(node)`: its box in page pixels, or null when not drawn), handed to every handler in its context; the store takes it as an option (none drawn when absent), the editor gives `pageLayout` of the coordinates module, and tests give fixed boxes. It serves a handler that acts on what a gesture covers on the page (`selection.marquee`). | A handler or any core module measuring the DOM; boxes passed as command arguments. |
| CSS support port | `src/core/ports/css.ts` | Whether the browser takes a value for a property (`supports`), handed to every handler in its context; the store takes it as an option (every value when absent), the editor gives its own `CSS.supports` (`src/editor/css-support.ts`, the same Chrome that draws the canvas) and tests give the answer they choose. style.set asks it before it writes a typed value (a negative Width is refused), the number fields before they step below zero. | A handler that writes a typed value without asking it; a core module calling `CSS.supports` itself. |
| Codecs | `src/core/style/codecs.ts` | The one reader and writer of a property's values, by the codec properties.json names for it (`registerCodec`, `codecOf`): the text a person typed read into a value of its kind (length-percentage: a number with a unit the property offers or a bare number in the field's unit, a keyword, calc()/min()/max()/clamp(), arithmetic on plain numbers worked out without evaluating code), and the CSS text a value is stored as (at most four decimals, `writeNumber`); `convertLength` between absolute units (the only conversion that keeps a size without measuring the page). What a property offers comes from the generated lists, whether the browser takes it from the CSS support port, both asked by style.set. | A second parser of a typed value; a unit list written in code. |
| i18n runtime | `src/i18n/index.ts` | `translate(locale, key, params)` and `translator(locale)` over the en (default) and pt-BR catalogues, `formatMessage`, `isLocale`, and `pluralForm` (which of a key's `.one` and `.other` texts a count takes, by `Intl.PluralRules`). | Icons | `tools/gen/icons.ts` | The one icon library is Lucide (DESIGN.md "Icons"). | Lint rules of the contract | `tools/lint/plugin.ts` | The ESLint rules `builder/use-ports`, `builder/no-literal-ui-string`, `builder/use-tokens` and `builder-css/use-tokens` (with `tools/lint/style-values.ts`, the value analysis both token rules share), and the owners of the canvas: `builder/pointer-owner` (pointer, mouse and drag listeners and props only in `src/editor/input/pointer.ts`; a control's onClick is allowed), `builder/gesture-owner` (`store.gesture()` only in the pointer owner, never in a handler) and `builder/frame-owner` (only the renderer writes the canvas iframe's DOM and CSS: `contentDocument`, `contentWindow` and `frames` are reached only by the canvas frame and the coordinates module, which write no DOM or stylesheet, and no other module imports the coordinates functions that hand out the page's elements), `builder/keyboard-owner` (keydown, keyup and keypress listeners and onKeyDown, onKeyUp and onKeyPress props only in the keymap) and `builder/no-manifest-id` (no string that is a CommandId, a DoorId or a PropertyId of `src/generated/ids.ts` written by hand, outside `src/generated/`, the manifest's reader and checker, the command table, the id a handler or predicate registers, a type, and the tests: code reads a command, a door or a property from the manifest's data). | Exceptions outside the owners named above. |

| Preference messages | `src/editor/preferences/said.ts` | What a preference change says in the status bar: the preference by its command's label, the value by its door's label (the manifest's); the handlers of the theme, the language, the view switches (`src/editor/view/overlays.ts`), the Elements view, the Layers row details and the inspector's mode ask it. | Autosave | `src/editor/persistence/autosave.ts` | (autosave-restore) The work kept between sessions: after every committed change of the document or the selection, one record holding the project's format version, the document and the selection is written at once (spec autosave-restore, Problems in Pager 1 and 2): first to a journal in localStorage, which is written before the page can unload, then to IndexedDB (database `work`, store `projects`, key `current`) in one transaction; the journal goes once IndexedDB holds its revision. At start (`src/main.tsx`) the newer of the two is read and restored through the project reader every open uses (`readProject`, archive.ts) before the editor is drawn, the history empty; a journal newer than the record is a crash's work, restored with a notice and written at once (autosave-crash-recovery). Every write is also a version (store `versions`, the last `autosave.versions`, each with its time). A record the reader refuses is kept untouched: Recovery required, the versions offered by the recovery dialog, nothing written until another project replaces the document (autosave-corruption-recovery). A refused write reads Not saved with its reason and is retried after `autosave.retryDelay`; while a change is not in IndexedDB, or a write was refused, leaving the tab asks the browser's confirmation (unsaved-work-guard). Only the tab that edits writes (multi-tab-guard). | Keymap | `src/editor/input/keymap.ts` | The only module that handles keys (lint rule `builder/keyboard-owner`). Runs the shortcut doors of the manifest in their key contexts: reads a key press as a chord, finds its door in the focused context or a context it inherits (`interactions.json`; the page body, where the focus rests after a press on the canvas, is the canvas context), prevents the browser default of a bound chord, and dispatches the door only when it runs by the shortcut rule (`src/editor/input/shortcut-rule.ts`, DESIGN.md "Build order": its command is built and its feature introduces the command or has all its commands built), which the door census and the scenario runner import as it is. A field keeps its keys (the `field` context) unless it names a context of its own with `data-key-context` (the inspector's text field: `element-text-field`, which inherits the field's). A shortcut whose command takes what the system clipboard holds (an argument of type `clipboard`: Ctrl+V while editing, `text.paste`) runs once the system clipboard module has read it, outside any gesture. A field that names its own key context (the inspector's text field, a number field) stands for its control's arguments for every key of that context (`focusedArgs`: a number field's property for its arrows and its Escape), and hands the text it holds as the command's one text argument the control and the door do not give (`content` of text.set, `value` of style.set and field.step). A shortcut door whose gesture gives a held key a meaning (a number field's arrows, the gesture number-field-keys: Shift ×10, Alt ×0.1) runs with that key held too when no door binds the chord itself, and hands the key as the command's `modifier` (`heldKeyBinding`). | A second key table; keys that are not doors; a copy of the shortcut rule. |
| The editor state | `src/editor/state.ts` | Composes the editor's part of the store state (`EditorUi`) from the parts panels.ts, layout.ts, preferences.ts, focus.ts, overlays.ts, menus/context-menu.ts, layers/tree.ts, layers/rename.ts, canvas/text-edit.ts, drag/drag-session.ts and core/structure/hand.ts own. | State of its own; document or selection state. |
| Layers folding | `src/editor/layers/tree.ts` | Which branches of the Layers tree are folded and what its search field holds (`ui.layers`, in memory only, never an undo step): `layers.setExpanded`, `layers.search` (the rows that match and the rows above them); `revealSelection` unfolds every folded branch that hides a selected node when the selection changes. The rows themselves are drawn by `src/editor/shell/sidebar.tsx`. | Document or selection state; saving the folds. |
| Renaming in Layers | `src/editor/layers/rename.ts` | The one inline rename of an element (spec rename-element): `layers.startRename` (F2 on the canvas, a double-click on a Layers row's name, the context menu's and Arrange's Rename) records the selected node in the editor state (`ui.rename`, never an undo step), with the Layers section shown (`showPanel`, panels.ts) and the branches that hide its row unfolded (`revealSelection`); a locked element, or one inside a locked element, is refused (`lockRefusal`). While it lasts, the node's row draws its name as a field holding the name, selected, with the focus (sidebar.tsx); Enter or leaving the field hands what it holds to `element.rename` (`src/core/nodes/names.ts`). The rename ends when an undoable command runs (element.rename among them) and when the selection is no longer its node alone (`selectedAlone`, selection.ts). | A dialog or a second rename path; the name being typed in the editor state (it is the field's own text until it is kept). |
| The editor store binding | `src/editor/store.ts` | Creates the store with the command table and the editor state, stores the preferences on every change, and exposes the store to React (`useEditorState` over `useSyncExternalStore`). | Holding state in `useState` or `useRef`. |

## Concepts of foundation part 2

| Concept | Owner | Responsibility |
|---|---|---|
| Canvas iframe | `src/editor/canvas/frame.tsx` | A same-origin iframe (srcdoc, sandbox without scripts) that only renders: no event handler, no pointer event (`pointer-events: none`); an overlay above it receives every pointer input. Scaled with the standard CSS `zoom`; the renderer mounts the document into it once and then applies each change the store publishes (`subscribeDocument`). The one exception is a text edited in place (the text editing surface below): while it lasts, the editor listens for keys on the frame's window (the keymap's own listener, which the frame installs and removes) and the frame is not `aria-hidden`, as it holds the focus; when it ends, the frame gives the focus back to the editor's page body. The page itself still carries no event handler or event attribute. |
| The text editing surface | `src/editor/canvas/text-edit.ts` | A text is edited in place on the page itself, in the zoomed iframe (spec text-edit-inline; text-inline-formatting edits the real inline markup there). `text.startEdit`, `text.cancelEdit` and `text.insertLineBreak` only record the edit in the editor state (`ui.textEdit`: the node, and the line breaks asked for); the canvas frame has the renderer carry it out (the edited element marked `contenteditable="plaintext-only"` and `data-key-context="text-editing"`, focused without scrolling with the caret at the end of its text, a `<br>` inserted at the caret, the text read back with each `<br>` as "\n", the marks removed and the document's text drawn again when the edit ends). `editArgs` hands the doors that keep the text (`text.set` by Enter and by a click outside the element) the node and what the edit holds (its plain text, or its whole tree of runs when something in it is marked or the node held marks, so marks taken off go too). The marks (spec text-inline-formatting): `text.toggleBold`, `text.toggleItalic`, `text.editLink` (with an address) and `text.paste` only ask for a change of them (`ui.textEdit.changes` and `change`, an `InlineChange` of the inline markup module); the canvas frame has the renderer read the edited element's runs and its text selection (`editedContent`), applies the change there (`applyInlineChange`) and has the renderer draw the result with the range it leaves selected (`showEdited`). `text.editLink` without an address opens the link prompt (`ui.textEdit.linkPrompt`, with the overlay dismissals counted then: a newer dismissal closes it, as the edit's end and the address do); the frame keeps the selection it acts on while the prompt holds the focus and gives the text the focus back when it closes. The edit ends when an undoable command runs, when Escape cancels it, and when the selection is no longer its node alone. It never writes the page (the renderer does), keeps no draft of the text in the store, and reads no key itself. |
