# Architecture

Every concept has one owner module. A second implementation of a concept that has an owner here is a defect; a new concept gets its line here, and its data in the manifest, in the same commit as its code. `manifest:check` rule `owner` fails when the owner of a command in `manifest/commands/*.json` differs from the table "Command owners" below.

Layers: `src/core/` is the document core in plain TypeScript (no React, no DOM); `src/editor/` is the React editor; `src/app/` wires the two; `src/manifest/` reads and checks the contract; `src/generated/` is written by `npm run gen` only; `tools/` runs in Node only.

## Concepts of foundation part 1

Each module below exists by the end of part 1; until a module lands, its line is the plan it follows.

| Concept | Owner | Responsibility | Never |
|---|---|---|---|
| Generated types and registries | `tools/gen/types.ts` | Writes `src/generated/` from the manifest and the catalogues: the id unions (CommandId, DoorId, PropertyId, ElementType, MessageId…), each command's argument types, the value lists the "generated" doors offer. | Hand edits in `src/generated/` (gen:check fails); logic in generated files. |
| Manifest at runtime | `src/manifest/runtime.ts` | Loads the manifest JSON once, parsed by its schemas, and answers lookups: a command, a door, a region's doors, the menus, the properties, the elements. | Re-listing manifest data in code; writing the manifest. |
| Command registry and the "not available yet" marker | `src/core/commands/registry.ts` | The contract of the command table: its type `CommandTable` (a key for every CommandId), `registerHandler` (with the handler, optionally the command owner's `current`: whether a door with given arguments stands for the state the store holds, which `src/editor/doors/current.ts` asks), the `NOT_AVAILABLE_YET` marker, `registerPredicate` (with, optionally, the predicate's `refusal`: the message its failure shows, which the store accepts only when it is the command's `refusalKey` or one of its manifest `refusals`, so a refusal can name what it refuses), the handler's context and outcome; and the same contract for features: `FeatureTable` (a key for every FeatureId), `registerFeature`, `isRegistered`. It holds no entries. | Doors, React, entries. |
| The command table | `src/app/commands.ts` | The one map from every command to its handler or `NOT_AVAILABLE_YET`, and the table of registered predicates; a missing or extra entry is a type error. | Handlers written inline; any other map of commands. |
| The feature table | `src/app/features.ts` | The one map from every feature of the manifest to `registerFeature(id)` (built) or `NOT_AVAILABLE_YET`, in the manifest's order, and `isFeatureBuilt`; a missing or extra entry is a type error (`FeatureTable` of the command registry). A feature is registered once every scenario of it runs and passes through every door it names: the scenario runner runs only registered features, and the census fails a registered feature with no scenario, a command it lists not built, or a scenario door that does not work yet. Plain data: the runner and the census read it in Node. | Deriving "built" from the commands (a feature is built when it is registered, never because its commands are); any other list of built features. |
| Document model | `src/core/document/model.ts` | The document JSON types (pages, the node tree, attributes, classes, styles by breakpoint and state, a node's `hidden` flag: true, absent while it shows, never on a page root; a node's `locked` flag: true, absent while it is unlocked, never on a page root; a text element's `inline`: the canonical tree of its marks, whose plain text is its `text`, absent while nothing is marked) with ids from the manifest, and the empty project. | DOM, rendering, storage. |
| Validation | `src/core/document/validate.ts` | Whole-tree validation of a document and its selection against the model and the manifest, on every commit. The model's rules (`ModelRules`, from the manifest) that every handler receives: element types, where each attribute applies and what its value is (`attributeValues`: value type, keywords, HTML attribute, catalogue name), properties, breakpoints, states, the page root's element. | Repairing or changing a document. |
| Store and dispatch | `src/core/store/store.ts` | The one store: document, selection, history, last message and the editor state; changes only through `dispatch(command)`; deep-freezes every state in development and tests. `canRun(command, args)` says whether a command would run now (built, its predicate holds, its handler does not refuse) and changes nothing: the context menu shows only what applies. `refusal(command, args)` says why not (not available yet, the predicate's refusal, the handler's), or null, and changes nothing either: a palette tile's creation drag draws the refusal its drop would meet. When a change moves the selection (any command, undo, redo), the editor state follows it through the editor's `followSelection` option (Layers unfolds a branch that hides a selected node, `src/editor/layers/tree.ts`; a text edit ends when its node is no longer the selection alone, `src/editor/canvas/text-edit.ts`, and so does a rename in Layers, `src/editor/layers/rename.ts`), and after a command it follows the command through `followCommand` (by the command's manifest data: an undoable command ends a text edit and a rename). | Changing state outside dispatch; React. |
| Transactions | `src/core/history/transaction.ts` | Applies JSON patches, records their inverses, drops patches that change nothing; one transaction per dispatch or per gesture, with the selection before and after. | Touching the history stacks. |
| History | `src/core/history/history.ts` | The undo and redo stacks, coalescing, `history.undo` and `history.redo`: undo restores the document and the selection before the command, redo the ones after; no entry for a command that changes nothing. | Storing snapshots of editor state; entries for non-undoable commands. |
| Clock port | `src/core/ports/clock.ts` | The only reader of the time (`Date.now`); tests pass a fixed clock. | Being bypassed: a lint rule forbids `Date.now` and `new Date()` elsewhere. |
| IdGenerator port | `src/core/ports/ids.ts` | The only source of ids (`crypto.randomUUID`); tests pass a counter. | Being bypassed: a lint rule forbids `Math.random` and `crypto.randomUUID` elsewhere. |
| Layout port | `src/core/ports/layout.ts` | Where the canvas draws each node of the page it shows (`box(node)`: its box in page pixels, or null when not drawn), handed to every handler in its context; the store takes it as an option (none drawn when absent), the editor gives `pageLayout` of the coordinates module, and tests give fixed boxes. It serves a handler that acts on what a gesture covers on the page (`selection.marquee`). | A handler or any core module measuring the DOM; boxes passed as command arguments. |
| i18n runtime | `src/i18n/index.ts` | `translate(locale, key, params)` and `translator(locale)` over the en (default) and pt-BR catalogues, `formatMessage`, `isLocale`, and `pluralForm` (which of a key's `.one` and `.other` texts a count takes, by `Intl.PluralRules`). It holds no state: the UI language is a preference in the store, and the editor translates for the locale the store holds (`src/editor/text.ts`). | UI text written in code (lint rule `builder/no-literal-ui-string`); a locale kept outside the store. |
| Tokens | `src/ui/tokens.css` | Every colour, type style, spacing, size, radius and shadow, generated from `design/final/tokens.json` by `tools/gen/tokens.ts`, which fails when an on-colour or a text colour reads below 4.5:1 on its background. | A literal colour, spacing, size, radius, shadow or font value in any other stylesheet (lint rule `builder-css/use-tokens`) or in a React style object (`builder/use-tokens`), and a `var()` of a custom property the tokens do not define. |
| Icons | `tools/gen/icons.ts` | The one icon library is Lucide (DESIGN.md "Icons"). Writes `manifest/generated/icons.json` (every Lucide name, which rules icon-name and icon-required check the manifest against) and `src/ui/icons.svg` (the sprite of the icons the manifest names: doors, menu anchors, glyphs, elements, keyword icons). | An icon chosen in component code; an inline SVG icon. |
| Lint rules of the contract | `tools/lint/plugin.ts` | The ESLint rules `builder/use-ports`, `builder/no-literal-ui-string`, `builder/use-tokens` and `builder-css/use-tokens` (with `tools/lint/style-values.ts`, the value analysis both token rules share), and the owners of the canvas: `builder/pointer-owner` (pointer, mouse and drag listeners and props only in `src/editor/input/pointer.ts`; a control's onClick is allowed), `builder/gesture-owner` (`store.gesture()` only in the pointer owner, never in a handler) and `builder/frame-owner` (only the renderer writes the canvas iframe's DOM and CSS: `contentDocument`, `contentWindow` and `frames` are reached only by the canvas frame and the coordinates module, which write no DOM or stylesheet, and no other module imports the coordinates functions that hand out the page's elements), `builder/keyboard-owner` (keydown, keyup and keypress listeners and onKeyDown, onKeyUp and onKeyPress props only in the keymap) and `builder/no-manifest-id` (no string that is a CommandId, a DoorId or a PropertyId of `src/generated/ids.ts` written by hand, outside `src/generated/`, the manifest's reader and checker, the command table, the id a handler or predicate registers, a type, and the tests: code reads a command, a door or a property from the manifest's data). | Exceptions outside the owners named above. |
| Panel visibility | `src/editor/workspace/panels.ts` | Which sidebar view is shown, and whether the sidebar, the Layers section, the inspector and each dock tab are open: `workspace.setPanelOpen`, `toggleLeftDock`, `toggleInspector`, `collapseDocks`, `toggleDeveloperTools`. What a panel is (its name, its place, whether it is open at the first start) it reads from `panels` of `layout.json`. `opensEmptyPanel` says whether a door's arguments only open a panel the shell draws no body for (panel bodies). `withInspector` shows or hides the inspector column (Ctrl+Alt+B, Ctrl+\, and Page properties, which shows it). | Sizes, positions, the dock's state or the active tab (layout.ts); the inspector's sections (`src/editor/inspector/sections.ts`); document or selection state. |

Part 1 builds the dock's state and its active tab; inspector-panel the inspector's tab (its tabs are the tab doors of the inspector header, in their order; absent while the first shows, `inspectorTab`; `withInspectorTab` shows one, for `setActiveTab` and Page properties; `inspectorTabDrawing` names the tab that draws a region, `inspector-<tab>`). | Which panels are open (panels.ts). |
| Preferences | `src/editor/preferences/preferences.ts` | The UI language and theme, and the inspector's collapsed sections (what they mean and their command: `src/editor/inspector/sections.ts`), stored and restored after reload. | Document state. |
| Autosave | `src/editor/persistence/autosave.ts` | (autosave-restore) The work kept between sessions: after every committed change of the document or the selection, one record holding the project's format version, the document and the selection is written at once (spec autosave-restore, Problems in Pager 1 and 2): first to a journal in localStorage, which is written before the page can unload, then to IndexedDB (database `work`, store `projects`, key `current`) in one transaction; the journal goes once IndexedDB holds its revision. | Scenario data | `src/manifest/scenario.ts` | The scenario contract's grammar and data: a node path is the node names from the fixture's root, a field follows `/@`; resolving a path to one node, applying a scenario's document diff (node values without ids), the empty project of a fresh profile, and matching the document the test port reads against the expectation. Fixtures are `manifest/features/fixtures/<id>.json`, validated by manifest:check (rule fixture) and loaded only through File › Open. | A second path grammar; a fixture loaded any way but the door. |
| Chords | `src/manifest/chord.ts` | How a shortcut door writes its keys: `normaliseChord` reads a chord (modifiers in a fixed order, a letter in upper case, the named keys), for manifest:check and for the keymap alike. | A second chord parser. |
| Keymap | `src/editor/input/keymap.ts` | The only module that handles keys (lint rule `builder/keyboard-owner`). Runs the shortcut doors of the manifest in their key contexts: reads a key press as a chord, finds its door in the focused context or a context it inherits (`interactions.json`; the page body, where the focus rests after a press on the canvas, is the canvas context), prevents the browser default of a bound chord, and dispatches the door only when it runs by the shortcut rule (`src/editor/input/shortcut-rule.ts`, DESIGN.md "Build order": its command is built and its feature introduces the command or has all its commands built), which the door census and the scenario runner import as it is. A shortcut whose command the focused control's door also runs (a palette tile under Enter) acts on what that control stands for (its `data-args`), and does nothing while that control is disabled; a text field of that control adds the text it holds as the command's `content` (the inspector's text field under Enter). A field keeps its keys (the `field` context) unless it names a context of its own with `data-key-context` (the inspector's text field: `element-text-field`, which inherits the field's). While a text is edited in place, the canvas frame installs the same listener on the frame's window, where those keys arrive; the edited element names its own key context (`text-editing`, a mark of the renderer), elements of either window are told apart by their own window's `HTMLElement`, and a shortcut in that context takes its arguments from the edit (`editArgs` of text-edit.ts: the node and the text it holds). While the keyboard's hand holds an element (`heldHand` of core/structure/hand.ts), the canvas context is replaced by the `hand` context (spec hand-keyboard-move, "Trigger"), which inherits nothing, and a shortcut there takes its arguments from the hand's aim (`aimArgs`: Enter's parent and index). A shortcut whose command takes what the system clipboard holds (an argument of type `clipboard`: Ctrl+V while editing, `text.paste`) runs once the system clipboard module has read it, outside any gesture. | A second key table; keys that are not doors; a copy of the shortcut rule. |
| The editor state | `src/editor/state.ts` | Composes the editor's part of the store state (`EditorUi`) from the parts panels.ts, layout.ts, preferences.ts, focus.ts, overlays.ts, menus/context-menu.ts, layers/tree.ts, layers/rename.ts, canvas/text-edit.ts, drag/drag-session.ts and core/structure/hand.ts own. | State of its own; document or selection state. |
| Layers folding | `src/editor/layers/tree.ts` | Which branches of the Layers tree are folded (`ui.layers`, in memory only, never an undo step): `layers.setExpanded`; `revealSelection` unfolds every folded branch that hides a selected node when the selection changes. The rows themselves are drawn by `src/editor/shell/sidebar.tsx`. | Document or selection state; saving the folds. |
| Renaming in Layers | `src/editor/layers/rename.ts` | The one inline rename of an element (spec rename-element): `layers.startRename` (F2 on the canvas, a double-click on a Layers row's name, the context menu's and Arrange's Rename) records the selected node in the editor state (`ui.rename`, never an undo step), with the Layers section shown (`showPanel`, panels.ts) and the branches that hide its row unfolded (`revealSelection`); a locked element, or one inside a locked element, is refused (`lockRefusal`). While it lasts, the node's row draws its name as a field holding the name, selected, with the focus (sidebar.tsx); Enter or leaving the field hands what it holds to `element.rename` (`src/core/nodes/names.ts`). The rename ends when an undoable command runs (element.rename among them) and when the selection is no longer its node alone (`selectedAlone`, selection.ts). | A dialog or a second rename path; the name being typed in the editor state (it is the field's own text until it is kept). |
| The editor store binding | `src/editor/store.ts` | Creates the store with the command table and the editor state, stores the preferences on every change, and exposes the store to React (`useEditorState` over `useSyncExternalStore`). | Holding state in `useState` or `useRef`. |
| Door rendering | `src/editor/doors/door.tsx` | Draws one door as the control its kind and face (`drawnAs`, `icon`) call for, disabled with "not available yet" when its command has the marker, or when the item it stands for arrives with a feature not built yet (a palette entry's `feature`, `isFeatureBuilt`), and unavailable when its predicate says so; `current.ts` says whether a door stands for the current state the store holds, by asking the `current` its command's owner registered; a door whose command is not built stands for none. | Controls that are not doors (except `data-local` ones DESIGN.md lists). |
| Door placement | `src/editor/doors/placement.ts` | The doors and menu buttons of a region, in their order (`layout.json`, `placement`). | Hand-written lists of buttons or menu items. |
| Menus | `src/editor/doors/menu.tsx` | Opens a menu from its button and draws its items, the menu doors in order with their shortcuts, its submenus (shown by CSS while hovered, focused or opened) and, under an open menu, the backdrop door `ui.dismiss#overlay-backdrop`; a menu closes when a dismissal newer than its opening arrives. It has no key or pointer listener: its keys are the doors of the "menu" key context. It draws the context menu too (`ContextMenu`) while `src/editor/menus/context-menu.ts` says it is open: the doors of the `context-menu` region whose command `store.canRun` (no disabled or "not available yet" item; nothing drawn when none applies), each with its command's key in the canvas context, at the last press (`pressPoint` of pointer.ts) moved inside the window by the `--space-4` token, over the backdrop; the focus goes to its first item and back where it was when it closes; a run item dismisses it (`ui.dismiss`). | Item tables written in code; key or pointer listeners. |
| Keyboard focus | `src/editor/focus/focus.ts` | `focus.next`, `focus.previous`, `focus.first`, `focus.last` and `focus.activate`: the handler records the request in the editor state (`ui.focus`); the owner's installer moves the DOM focus among the items of the region that names the focused key context (its own focusable controls, not those of a region nested in it), or runs the focused item. | Moving the focus from a handler; a region's items listed by hand. |
| Overlays | `src/editor/menus/overlays.ts` | `ui.dismiss`: counts the dismissals in the editor state (`ui.overlays`); an open menu closes when one arrives. | Which menu is open (the menu's own state). |
| Context menu | `src/editor/menus/context-menu.ts` | `contextMenu.open`: the node becomes the selection unless it is already selected (a multi-selection is kept), and the opening is recorded with the dismissals so far (`ui.contextMenu`), so the next dismissal closes it; never an undo step. | Which items it shows or where (menu.tsx). |
| The shell regions | `src/editor/shell/shell.tsx` | The window grid and every region of DESIGN.md, one file each under `src/editor/shell/`: top bar (`top-bar.tsx`), activity bar and sidebar views (`sidebar.tsx`), file tabs, canvas toolbar, canvas frame with breakpoint tabs and rulers (`canvas.tsx`), inspector (`inspector.tsx`: the body of the tab its header shows, from `TAB_BODIES`, where a tab with no body is not available yet; the Style tab's region is as tall as what it shows, inside the scrolling column; the Settings tab's text field names the key context `element-text-field`, whose doors keep the text (Enter, `text.set`) or put it back (Escape, `text.cancelEdit`), shows the document's text after every message, and keeps what was typed when it is left, after the pointer gesture of a press elsewhere ends; on the page root, each field of the page's settings is the one field of a form of its own, so Enter submits it as the browser submits a form implicitly (no key handled there), and the submission, leaving the field or its going keeps a text other than the one it last showed or kept with `page.setSetting`, the same way after the pointer gesture; a field whose door's feature is not registered as built is not available yet, although the command it shares is), dock (`dock.tsx`), status bar (`status-bar.tsx`: the last message, or during a palette tile's creation drag the drag's words, `dragWords` of the canvas chrome), the toast that follows a delete (`toast.tsx`: the delete's message and the region's Undo door, shown while `followsDelete` of `src/core/structure/remove.ts` holds, so there is one at most, a new delete replaces it and the next message takes it away; no timer, no stack); `slots.tsx` draws a region's slots in order; `shell.css` styles them from the tokens only. | Drawing a control a door does not declare. |
| Panel bodies | `src/editor/shell/bodies.ts` | Whether a panel has its content: the shell draws a body for it. Read from the tables the bodies are drawn from (`SIDEBAR_VIEWS` in `sidebar.tsx`, `DOCK_TABS` in `dock.tsx`; a section follows its view; the inspector column, the canvas tools and the workbench are the shell's own frame) and handed to the doors by `shell.tsx` (`PanelBodies`): a door whose only effect is to open a panel without a body is not available yet, and the panel says so. | A status of a panel written by hand; a body drawn from outside its table. |

## Concepts of foundation part 2

| Concept | Owner | Responsibility |
|---|---|---|
| Canvas iframe | `src/editor/canvas/frame.tsx` | A same-origin iframe (srcdoc, sandbox without scripts) that only renders: no event handler, no pointer event (`pointer-events: none`); an overlay above it receives every pointer input. Scaled with the standard CSS `zoom`; the renderer mounts the document into it once and then applies each change the store publishes (`subscribeDocument`). The one exception is a text edited in place (the text editing surface below): while it lasts, the editor listens for keys on the frame's window (the keymap's own listener, which the frame installs and removes) and the frame is not `aria-hidden`, as it holds the focus; when it ends, the frame gives the focus back to the editor's page body. The page itself still carries no event handler or event attribute. |
| The text editing surface | `src/editor/canvas/text-edit.ts` | A text is edited in place on the page itself, in the zoomed iframe (spec text-edit-inline; text-inline-formatting edits the real inline markup there). `text.startEdit`, `text.cancelEdit` and `text.insertLineBreak` only record the edit in the editor state (`ui.textEdit`: the node, and the line breaks asked for); the canvas frame has the renderer carry it out (the edited element marked `contenteditable="plaintext-only"` and `data-key-context="text-editing"`, focused without scrolling with the caret at the end of its text, a `<br>` inserted at the caret, the text read back with each `<br>` as "\n", the marks removed and the document's text drawn again when the edit ends). `editArgs` hands the doors that keep the text (`text.set` by Enter and by a click outside the element) the node and what the edit holds (its plain text, or its whole tree of runs when something in it is marked or the node held marks, so marks taken off go too). The marks (spec text-inline-formatting): `text.toggleBold`, `text.toggleItalic`, `text.editLink` (with an address) and `text.paste` only ask for a change of them (`ui.textEdit.changes` and `change`, an `InlineChange` of the inline markup module); the canvas frame has the renderer read the edited element's runs and its text selection (`editedContent`), applies the change there (`applyInlineChange`) and has the renderer draw the result with the range it leaves selected (`showEdited`). `text.editLink` without an address opens the link prompt (`ui.textEdit.linkPrompt`, with the overlay dismissals counted then: a newer dismissal closes it, as the edit's end and the address do); the frame keeps the selection it acts on while the prompt holds the focus and gives the text the focus back when it closes. The edit ends when an undoable command runs, when Escape cancels it, and when the selection is no longer its node alone. It never writes the page (the renderer does), keeps no draft of the text in the store, and reads no key itself. |
| Inline markup | `src/core/text/inline.ts` | The marks a text element's text may carry (bold `<strong>`, italic `<em>`, links `<a href>`) as a tree of runs, its canonical form (adjacent runs with the same marks joined, a link outside bold outside italic, links never nested), the one rule of the address a link may have, inside text or on a Link Block (`isSafeHref`: http, https, mailto, tel; `element.setLink` asks it too), a change of the marks over a range of characters (`applyInlineChange`: a mark toggled over the range only, splitting runs; a link's address set or removed; runs inserted; a caret takes the link or the word it touches), a marked text written anew as plain text (`withText`: what it keeps keeps its marks), and pasted markup read as marked text (`pastedRuns`: the marks kept, metadata elements dropped, elements that are not phrasing content on lines of their own, by the content model's categories). Pure. | The DOM; a second list of marks or of allowed addresses. |
| Text toolbar | `src/editor/canvas/text-toolbar.tsx` | While a text is edited in place, the doors of the `text-toolbar` region (Bold, Italic, Link), titled with their keys in the text editing context, placed by the canvas chrome above the edit's label; and, while `text.editLink` asks for an address, the link prompt under it (a portal on the body): its field (typing there is not a command), filled with the address of the link the selection is in and focused once the panel is placed, whose Enter answers `text.editLink` with the address, the refusal of an address shown under it, and the backdrop door `ui.dismiss#overlay-backdrop` under it. | Writing the page; keys of its own (Enter is the form's own submission). |
| System clipboard | `src/editor/clipboard.ts` | The one reader of the browser's clipboard (`readClipboard`): its HTML parsed into an inert document and handed on as a tree of texts and elements, its plain text, or the browser's refusal (`ClipboardContent`, the type of a command argument of type `clipboard`). A door whose command takes the clipboard reads it here and runs the command with it (the keymap for `text.paste`). | Deciding what to paste; keeping what it read. |
| Renderer | `src/core/render/render.ts` | The document JSON to the HTML and CSS of the page, the one writer of CSS text from stored values: every element carries `data-node`, every node's rules sit in its own `style[data-node-style]`, breakpoints are max-width media queries, states pseudo-classes. The page root is the page's `<body>`, and the settings of the page it stores (`isPageSetting` of `src/core/page/settings.ts`) write their HTML attributes (`lang`, `dir`) on the page's `<html>`, never on `<body>` (spec page-properties, Problems in Pager 4). Editor-only, never in the document nor an export: a container below the page root carries `data-container`, and the editor's `style[data-editor-style]` gives an empty one the minimum height of `canvas.emptyContainerMinHeight`; the element of a hidden node carries `data-hidden`, which the same style element draws with `display: none !important` (spec hide-element: its subtree goes with it, and showing it removes the mark, so the layout it had comes back); the element of a text edited in place carries the marks of the edit (the text editing surface). A text element's text is drawn with its inline marks (`<strong>`, `<em>`, `<a href>`, a `<br>` for each line break); while it is edited, the renderer reads it back as runs with its text selection as a range of characters and draws it again with the runs and range a change of its marks produced. It applies a change's patches to the elements they touch and keeps every other element as it is; it never re-renders the whole page for a change. |
| Coordinates under zoom | `src/editor/canvas/coordinates.ts` | Page, frame and screen coordinates at any zoom (the frame's `currentCSSZoom`, its border and padding, the page's scroll); the element under a screen point and an element's box on the screen, which it hands to the rest of the editor only as a node (`nodeAt`: the node under a point, the page root where no element is; `nodesUnder`: every node under a point, the deepest first, for a drag that looks past the dragged element), a node's screen box (`nodeBox`) and flow axis (`flowAxis`: a flex row lays its children along x, every other flow along y), and to the core as the layout port (`pageLayout`: a node's box in page pixels), and the CSS computed values of a node's element (`computedValues`, through the typed object model: the values in force whatever sets them, which the inspector's collapsed sections summarise). It only reads the page. |
| ZIP archives | `src/core/project/zip.ts` | The one writer of the archives the editor hands out (project.zip, the export): standard ZIP, entries stored with their CRC-32, UTF-8 names and the given modification time, so the same entries at the same time give the same bytes. Pure. | Compressing with a library of its own per caller; a second archive writer. |
| Download port | `src/core/ports/download.ts` | The one way a command hands the person a file: a handler returns the file in its `change` outcome (`download`) and stays pure; the store gives it to the port once the command has run.
