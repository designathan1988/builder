# Architecture

Every concept has one owner module. A second implementation of a concept that has an owner here is a defect; a new concept gets its line here, and its data in the manifest, in the same commit as its code. `manifest:check` rule `owner` fails when the owner of a command in `manifest/commands/*.json` differs from the table "Command owners" below.

Layers: `src/core/` is the document core in plain TypeScript (no React, no DOM); `src/editor/` is the React editor; `src/app/` wires the two; `src/manifest/` reads and checks the contract; `src/generated/` is written by `npm run gen` only; `tools/` runs in Node only.

## Concepts of foundation part 1

Each module below exists by the end of part 1; until a module lands, its line is the plan it follows.

| Concept | Owner | Responsibility | Never |

| Command registry and the "not available yet" marker | `src/core/commands/registry.ts` | The contract of the command table: its type `CommandTable` (a key for every CommandId), `registerHandler` (with the handler, optionally the command owner's `current`: whether a door with given arguments stands for the state the store holds, which `src/editor/doors/current.ts` asks), the `NOT_AVAILABLE_YET` marker, `registerPredicate` (with, optionally, the predicate's `refusal`: the message its failure shows, which the store accepts only when it is the command's `refusalKey` or one of its manifest `refusals`, so a refusal can name what it refuses), the handler's context and outcome; and the same contract for features: `FeatureTable` (a key for every FeatureId), `registerFeature`, `isRegistered`. A feature is registered once every scenario of it runs and passes through every door it names: the scenario runner runs only registered features, and the census fails a registered feature with no scenario, a command it lists not built, or a scenario door that does not work yet. Plain data: the runner and the census read it in Node. | Deriving "built" from the commands (a feature is built when it is registered, never because its commands are); any other list of built features. |
| Document model | `src/core/document/model.ts` | The document JSON types (pages, the node tree, attributes, classes, styles by breakpoint and state) with ids from the manifest, and the empty project. | DOM, rendering, storage. |

| Store and dispatch | `src/core/store/store.ts` | The one store: document, selection, history, last message and the editor state; changes only through `dispatch(command)`; deep-freezes every state in development and tests. `canRun(command, args)` says whether a command would run now (built, its predicate holds, its handler does not refuse) and changes nothing: the context menu shows only what applies. `refusal(command, args)` says why not (not available yet, the predicate's refusal, the handler's), or null, and changes nothing either: a palette tile's creation drag draws the refusal its drop would meet. | Transactions | `src/core/history/transaction.ts` | Applies JSON patches, records their inverses, drops patches that change nothing; one transaction per dispatch or per gesture, with the selection before and after. | Touching the history stacks. |
| History | `src/core/history/history.ts` | The undo and redo stacks, coalescing, `history.undo` and `history.redo`: undo restores the document and the selection before the command, redo the ones after; no entry for a command that changes nothing. | Storing snapshots of editor state; entries for non-undoable commands. |
| Clock port | `src/core/ports/clock.ts` | The only reader of the time (`Date.now`); tests pass a fixed clock. | Being bypassed: a lint rule forbids `Date.now` and `new Date()` elsewhere. |
| IdGenerator port | `src/core/ports/ids.ts` | The only source of ids (`crypto.randomUUID`); tests pass a counter. | Being bypassed: a lint rule forbids `Math.random` and `crypto.randomUUID` elsewhere. |
| Layout port | `src/core/ports/layout.ts` | Where the canvas draws each node of the page it shows (`box(node)`: its box in page pixels, or null when not drawn), handed to every handler in its context; the store takes it as an option (none drawn when absent), the editor gives `pageLayout` of the coordinates module, and tests give fixed boxes. It serves a handler that acts on what a gesture covers on the page (`selection.marquee`). | A handler or any core module measuring the DOM; boxes passed as command arguments. |
| i18n runtime | `src/i18n/index.ts` | `translate(locale, key, params)` and `translator(locale)` over the en (default) and pt-BR catalogues, `formatMessage`, `isLocale`, and `pluralForm` (which of a key's `.one` and `.other` texts a count takes, by `Intl.PluralRules`). | Tokens | `src/ui/tokens.css` | Every colour, type style, spacing, size, radius and shadow, generated from `design/final/tokens.json` by `tools/gen/tokens.ts`, which fails when an on-colour or a text colour reads below 4.5:1 on its background. | A literal colour, spacing, size, radius, shadow or font value in any other stylesheet (lint rule `builder-css/use-tokens`) or in a React style object (`builder/use-tokens`), and a `var()` of a custom property the tokens do not define. |
| Icons | `tools/gen/icons.ts` | The one icon library is Lucide (DESIGN.md "Icons"). Writes `manifest/generated/icons.json` (every Lucide name, which rules icon-name and icon-required check the manifest against) and `src/ui/icons.svg` (the sprite of the icons the manifest names: doors, menu anchors, glyphs, elements, keyword icons). | An icon chosen in component code; an inline SVG icon. |
| Lint rules of the contract | `tools/lint/plugin.ts` | The ESLint rules `builder/use-ports`, `builder/no-literal-ui-string`, `builder/use-tokens` and `builder-css/use-tokens` (with `tools/lint/style-values.ts`, the value analysis both token rules share), and the owners of the canvas: `builder/pointer-owner` (pointer, mouse and drag listeners and props only in `src/editor/input/pointer.ts`; a control's onClick is allowed), `builder/gesture-owner` (`store.gesture()` only in the pointer owner, never in a handler) and `builder/frame-owner` (only the renderer writes the canvas iframe's DOM and CSS: `contentDocument`, `contentWindow` and `frames` are reached only by the canvas frame and the coordinates module, which write no DOM or stylesheet, and no other module imports the coordinates functions that hand out the page's elements), `builder/keyboard-owner` (keydown, keyup and keypress listeners and onKeyDown, onKeyUp and onKeyPress props only in the keymap) and `builder/no-manifest-id` (no string that is a CommandId, a DoorId or a PropertyId of `src/generated/ids.ts` written by hand, outside `src/generated/`, the manifest's reader and checker, the command table, the id a handler or predicate registers, a type, and the tests: code reads a command, a door or a property from the manifest's data). | Exceptions outside the owners named above. |
| Panel visibility | `src/editor/workspace/panels.ts` | Which sidebar view is shown, and whether the sidebar, the Layers section, the inspector and each dock tab are open: `workspace.setPanelOpen`, `toggleLeftDock`, `toggleInspector`, `collapseDocks`, `toggleDeveloperTools`. What a panel is (its name, its place, whether it is open at the first start) it reads from `panels` of `layout.json`. `opensEmptyPanel` says whether a door's arguments only open a panel the shell draws no body for (panel bodies). | Sizes, positions, the dock's state or the active tab (layout.ts); the inspector's sections (`src/editor/inspector/sections.ts`); document or selection state. |
| Workspace layout | `src/editor/workspace/layout.ts` | The dock's state (collapsed, open, maximised), the active tab of each tab group, splitter sizes and floating panel positions: `workspace.setWorkbenchState`, `setActiveTab`, `resizeSplitter`, `movePanel`, `reset`. | Preferences | `src/editor/preferences/preferences.ts` | The UI language and theme, stored and restored after reload. | Document state. |
| Autosave | `src/editor/persistence/autosave.ts` | (autosave-restore) The work kept between sessions: after every committed change of the document or the selection, one record holding the project's format version, the document and the selection is written at once (spec autosave-restore, Problems in Pager 1 and 2): first to a journal in localStorage, which is written before the page can unload, then to IndexedDB (database `work`, store `projects`, key `current`) in one transaction; the journal goes once IndexedDB holds its revision. At start (`src/main.tsx`) the newer of the two is read and restored through the project reader every open uses (`readProject`, archive.ts) before the editor is drawn, the history empty; a record the model refuses is kept and never overwritten in that session. The status bar's save state (Not saved, Saving…, Saved, Save failed) comes from it. | Preferences; a second record for the selection; waiting before a write; a second reader of a project document. |
| Scenario data | `src/manifest/scenario.ts` | The scenario contract's grammar and data: a node path is the node names from the fixture's root, a field follows `/@`; resolving a path to one node, applying a scenario's document diff (node values without ids), the empty project of a fresh profile, and matching the document the test port reads against the expectation. Fixtures are `manifest/features/fixtures/<id>.json`, validated by manifest:check (rule fixture) and loaded only through File › Open. | A second path grammar; a fixture loaded any way but the door. |
| Chords | `src/manifest/chord.ts` | How a shortcut door writes its keys: `normaliseChord` reads a chord (modifiers in a fixed order, a letter in upper case, the named keys), for manifest:check and for the keymap alike. | A second chord parser. |
| Keymap | `src/editor/input/keymap.ts` | The only module that handles keys (lint rule `builder/keyboard-owner`). Runs the shortcut doors of the manifest in their key contexts: reads a key press as a chord, finds its door in the focused context or a context it inherits (`interactions.json`; the page body, where the focus rests after a press on the canvas, is the canvas context), prevents the browser default of a bound chord, and dispatches the door only when it runs by the shortcut rule (`src/editor/input/shortcut-rule.ts`, DESIGN.md "Build order": its command is built and its feature introduces the command or has all its commands built), which the door census and the scenario runner import as it is. A shortcut whose command the focused control's door also runs (a palette tile under Enter) acts on what that control stands for (its `data-args`), and does nothing while that control is disabled. While a text is edited in place, the canvas frame installs the same listener on the frame's window, where those keys arrive; the edited element names its own key context (`text-editing`, a mark of the renderer), elements of either window are told apart by their own window's `HTMLElement`, and a shortcut in that context takes its arguments from the edit (`editArgs` of text-edit.ts: the node and the text it holds). | A second key table; keys that are not doors; a copy of the shortcut rule. |
| The editor state | `src/editor/state.ts` | Composes the editor's part of the store state (`EditorUi`) from the parts panels.ts, layout.ts, preferences.ts, focus.ts, overlays.ts, menus/context-menu.ts, layers/tree.ts, canvas/text-edit.ts and drag/drag-session.ts own. | State of its own; document or selection state. |
| Layers folding | `src/editor/layers/tree.ts` | Which branches of the Layers tree are folded (`ui.layers`, in memory only, never an undo step): `layers.setExpanded`; `revealSelection` unfolds every folded branch that hides a selected node when the selection changes. The rows themselves are drawn by `src/editor/shell/sidebar.tsx`. | Document or selection state; saving the folds. |
| The editor store binding | `src/editor/store.ts` | Creates the store with the command table and the editor state, stores the preferences on every change, and exposes the store to React (`useEditorState` over `useSyncExternalStore`). | Holding state in `useState` or `useRef`. |
| Door rendering | `src/editor/doors/door.tsx` | Draws one door as the control its kind and face (`drawnAs`, `icon`) call for, disabled with "not available yet" when its command has the marker, or when the item it stands for arrives with a feature not built yet (a palette entry's `feature`, `isFeatureBuilt`), and unavailable when its predicate says so; `current.ts` says whether a door stands for the current state the store holds, by asking the `current` its command's owner registered; a door whose command is not built stands for none. | Controls that are not doors (except `data-local` ones DESIGN.md lists). |
| Door placement | `src/editor/doors/placement.ts` | The doors and menu buttons of a region, in their order (`layout.json`, `placement`). | Hand-written lists of buttons or menu items. |
| Menus | `src/editor/doors/menu.tsx` | Opens a menu from its button and draws its items, the menu doors in order with their shortcuts, its submenus (shown by CSS while hovered, focused or opened) and, under an open menu, the backdrop door `ui.dismiss#overlay-backdrop`; a menu closes when a dismissal newer than its opening arrives. It has no key or pointer listener: its keys are the doors of the "menu" key context. It draws the context menu too (`ContextMenu`) while `src/editor/menus/context-menu.ts` says it is open: the doors of the `context-menu` region whose command `store.canRun` (no disabled or "not available yet" item; nothing drawn when none applies), each with its command's key in the canvas context, at the last press (`pressPoint` of pointer.ts) moved inside the window by the `--space-4` token, over the backdrop; the focus goes to its first item and back where it was when it closes; a run item dismisses it (`ui.dismiss`). | Item tables written in code; key or pointer listeners. |
| Keyboard focus | `src/editor/focus/focus.ts` | `focus.next`, `focus.previous`, `focus.first`, `focus.last` and `focus.activate`: the handler records the request in the editor state (`ui.focus`); the owner's installer moves the DOM focus among the items of the region that names the focused key context (its own focusable controls, not those of a region nested in it), or runs the focused item. | Moving the focus from a handler; a region's items listed by hand. |
| Overlays | `src/editor/menus/overlays.ts` | `ui.dismiss`: counts the dismissals in the editor state (`ui.overlays`); an open menu closes when one arrives. | Which menu is open (the menu's own state). |
| Context menu | `src/editor/menus/context-menu.ts` | `contextMenu.open`: the node becomes the selection unless it is already selected (a multi-selection is kept), and the opening is recorded with the dismissals so far (`ui.contextMenu`), so the next dismissal closes it; never an undo step. | Which items it shows or where (menu.tsx). |
| The shell regions | `src/editor/shell/shell.tsx` | The window grid and every region of DESIGN.md, one file each under `src/editor/shell/`: top bar (`top-bar.tsx`), activity bar and sidebar views (`sidebar.tsx`), file tabs, canvas toolbar, canvas frame with breakpoint tabs and rulers (`canvas.tsx`), inspector (`inspector.tsx`), dock (`dock.tsx`), status bar (`status-bar.tsx`: the last message, or during a palette tile's creation drag the drag's words, `dragWords` of the canvas chrome), the toast that follows a delete (`toast.tsx`: the delete's message and the region's Undo door, shown while `followsDelete` of `src/core/structure/remove.ts` holds, so there is one at most, a new delete replaces it and the next message takes it away; no timer, no stack); `slots.tsx` draws a region's slots in order; `shell.css` styles them from the tokens only. | Drawing a control a door does not declare. |
| Panel bodies | `src/editor/shell/bodies.ts` | Whether a panel has its content: the shell draws a body for it. Read from the tables the bodies are drawn from (`SIDEBAR_VIEWS` in `sidebar.tsx`, `DOCK_TABS` in `dock.tsx`; a section follows its view; the inspector column, the canvas tools and the workbench are the shell's own frame) and handed to the doors by `shell.tsx` (`PanelBodies`): a door whose only effect is to open a panel without a body is not available yet, and the panel says so. | A status of a panel written by hand; a body drawn from outside its table. |

## Concepts of foundation part 2

| Concept | Owner | Responsibility |
|---|---|---|
| Canvas iframe | `src/editor/canvas/frame.tsx` | A same-origin iframe (srcdoc, sandbox without scripts) that only renders: no event handler, no pointer event (`pointer-events: none`); an overlay above it receives every pointer input. Scaled with the standard CSS `zoom`; the renderer mounts the document into it once and then applies each change the store publishes (`subscribeDocument`). The one exception is a text edited in place (the text editing surface below): while it lasts, the editor listens for keys on the frame's window (the keymap's own listener, which the frame installs and removes) and the frame is not `aria-hidden`, as it holds the focus; when it ends, the frame gives the focus back to the editor's page body. The page itself still carries no event handler or event attribute. |
| The text editing surface | `src/editor/canvas/text-edit.ts` | A text is edited in place on the page itself, in the zoomed iframe (spec text-edit-inline; text-inline-formatting edits the real inline markup there). `text.startEdit`, `text.cancelEdit` and `text.insertLineBreak` only record the edit in the editor state (`ui.textEdit`: the node, and the line breaks asked for); the canvas frame has the renderer carry it out (the edited element marked `contenteditable="plaintext-only"` and `data-key-context="text-editing"`, focused without scrolling with the caret at the end of its text, a `<br>` inserted at the caret, the text read back with each `<br>` as "\n", the marks removed and the document's text drawn again when the edit ends). `editArgs` hands the doors that keep the text (`text.set` by Enter and by a click outside the element) the node and the text the edit holds. The edit ends when an undoable command runs, when Escape cancels it, and when the selection is no longer its node alone. It never writes the page (the renderer does), keeps no draft of the text in the store, and reads no key itself. |
| Renderer | `src/core/render/render.ts` | The document JSON to the HTML and CSS of the page, the one writer of CSS text from stored values: every element carries `data-node`, every node's rules sit in its own `style[data-node-style]`, breakpoints are max-width media queries, states pseudo-classes. Editor-only, never in the document nor an export: a container below the page root carries `data-container`, and the editor's `style[data-editor-style]` gives an empty one the minimum height of `canvas.emptyContainerMinHeight`; the element of a text edited in place carries the marks of the edit (the text editing surface). It applies a change's patches to the elements they touch and keeps every other element as it is; it never re-renders the whole page for a change. |
| Coordinates under zoom | `src/editor/canvas/coordinates.ts` | Page, frame and screen coordinates at any zoom (the frame's `currentCSSZoom`, its border and padding, the page's scroll); the element under a screen point and an element's box on the screen, which it hands to the rest of the editor only as a node (`nodeAt`: the node under a point, the page root where no element is; `nodesUnder`: every node under a point, the deepest first, for a drag that looks past the dragged element), a node's screen box (`nodeBox`) and flow axis (`flowAxis`: a flex row lays its children along x, every other flow along y), and to the core as the layout port (`pageLayout`: a node's box in page pixels). It only reads the page. |
| ZIP archives | `src/core/project/zip.ts` | The one writer of the archives the editor hands out (project.zip, the export): standard ZIP, entries stored with their CRC-32, UTF-8 names and the given modification time, so the same entries at the same time give the same bytes. Pure. | Compressing with a library of its own per caller; a second archive writer. |
| Download port | `src/core/ports/download.ts` | The one way a command hands the person a file: a handler returns the file in its `change` outcome (`download`) and stays pure; the store gives it to the port once the command has run. The editor's port (`src/editor/download.ts`) saves it through the browser; tests pass their own or none. | A handler that touches the DOM or the browser's downloads. |
| Project file | `src/core/project/archive.ts` | File › Save project (`project.save`, spec project-save-json): project.zip holding project.json, the document alone as the editor holds it (the format version every reader opens), its save time only as the entries' time. File › Open (`project.open`): reads a project document (the fixtures' format) through the browser's file chooser (`useDoor` asks for a command's required `file` argument), refuses one the model rejects or of a newer version, and replaces the document (outcome `load`: selection and history start empty). `readProject` is the one reader of a project document: File › Open and the autosaved work restored at start both load through it. |
| Pointer input | `src/editor/input/pointer.ts` | The one owner of pointer, mouse and drag input on the canvas (the overlay and the stage around the page). Each press is one gesture of an explicit state machine (idle, pressed, dragging; `drag.threshold` from interactions.json turns a press into a drag); the press's door is found by its data (a canvas click's target, button, count and modifier) and runs, with every door of the gesture, through one transaction the owner opens with `store.gesture()` at the press and commits at the release, or cancels when the browser takes the pointer away: one gesture, one undo step. While a gesture is open the keys are read in the drag key context and run through it. A drag pressed on the empty area of the page or of a container (not on a child) is the marquee (`selection.marquee#canvas-drag-empty-area-page-or-container`, its mode from the gesture's modifier at the press): on every move the gesture is cancelled back to the selection held before the press (so what the press's click, add or toggle did is undone) and opened again with the band from the press to the pointer, in page pixels, so the selection follows the band live and the release commits the last one. A press on the selected element's name label on the canvas chrome (`data-label-for`, spec select-click "Hit zones") is a press on that element, and never a marquee. A primary press on any other element (a leaf, or an empty container, whose marquee could take nothing), or on a label, that becomes a drag drags the selection's roots: each move asks the drop proposal (below) where they would land, the drawn proposal changes only past `drag.hysteresis`, and the release runs the canvas-drag door of its zone (`before-after`, or `inside` for a drop into a container and a refused one) with its parent and index inside the gesture. Once `palette-drag-insert` is registered in the feature table, a primary press on an available palette tile (the tile door of the command whose canvas-drag door takes a `palette-tile` source) is a gesture too (spec palette-drag-insert): released below the threshold it runs the tile's door at the release (the tile's onClick then runs only an activation with no press, `pressedByPointer`); past it, it is a creation drag with nothing dragged, which asks the same drop proposal only while the pointer is over the page (the canvas overlay; over the stage or a panel it has none), asks the store why its command would refuse the entry there (`store.refusal`), and whose release runs `element.insert#canvas-drag-palette-tile-drop-proposal` with the tile's entry and the drawn proposal's parent and index inside the gesture (the command refuses a parent that does not accept it; with no proposal nothing runs). A cancellation that `drag.cancel` records (drag-session.ts) newer than the open gesture cancels it, so the release after it drops nothing. While a press on the canvas is held, the browser's own text selection and drag and drop are prevented. It publishes the hovered node, the marquee's band (screen pixels) and the drag in progress (the dragged nodes or the palette entry a creation drag inserts, the drawn proposal, the refusal it would meet, and the pointer's screen position) for the canvas chrome, and `modifierOf`, the one reading of the key a click holds, which a panel control drawn for several doors of one gesture (a Layers row: click, Shift+click, Ctrl+click) uses to run the door of that key. It keeps the screen point of the last press anywhere (`pressPoint`: the context menu opens there), keeps the browser's own menu from opening on the canvas and over the context menu and its backdrop, and a secondary press there from moving the focus (the menu it opens takes it). A Layers row's secondary click is the row's own control (its `onContextMenu`, like its `onClick`). A press is a single click (Chrome's `pointerdown` carries no click count); a double click is the browser's `dblclick`, whose door (a text element's `text.startEdit#canvas-double-click-text-element`) runs as a gesture of its own. While a text is edited, a press anywhere but on it keeps the text: the edit's node and text are read at the press, the press's own door runs (selecting there, which ends the edit), and the keeping door (`text.set#canvas-click-outside-edited-element`, recorded once per dispatch, so never inside a gesture) runs once the gesture closes, so the press is one undo step and the status bar ends on the kept text; a press that starts an edit or lands on the edited text prevents the mousedown's default, so the focus stays in the text. |
| Canvas chrome | `src/editor/canvas/chrome.tsx` | What the editor draws over the page, on the canvas overlay, never a pointer target: the outline of every selected node, the primary's label (its name and its exported tag, so the page root reads `body`) placed by the label rule (DESIGN.md "Canvas": above, else inside the top-left corner, else below, never over page text or a replaced element, whose boxes `contentBoxes` of the coordinates module gives); with several selected, the dashed outline of their union and, in place of the name, one label counting them (`canvas.selectedCount`) placed by the same rule on the union; the thinner outline of the node pointer.ts says is hovered; the marquee's band while pointer.ts draws one; and during a drag pointer.ts publishes, the drop indicator (the insertion line across the receiver at the gap or at the inside slot, the receiver's outline, dashed with no line into a container with no other child and in the danger colour when refused, the label `canvas.dropTarget`, or the refusal, placed by the label rule beside the line or the receiver), with the dragged selection's outline dashed and its label hidden. A palette tile's creation drag (spec palette-drag-insert) draws the same indicator with the label `canvas.insertTarget` (`canvas.insertInto` into a receiver with no child), or, where `store.refusal` says the element's command refuses the drop, the refused indicator with that refusal and no line; the selection's outline stays solid; its ghost (the element's icon and name, a portal on the body at `drag.ghostOffset` from the pointer, never a pointer target) follows the pointer over the whole window. `dragWords` gives the words of the drag in progress, which the status bar shows during a creation drag (off the page, `status.drop.outsidePage`). While a text is edited in place (`ui.textEdit`), its outline and label wear the text editing mode colour and the label reads `canvas.editingText` (spec text-edit-inline, Problems in Pager 2). Boxes come from `nodeBox`, measured each animation frame while something is drawn. | Writing the page; taking pointer events, except a label that names one element (read by pointer.ts, no listener here); selection state of its own. |
| Drop proposal | `src/editor/drag/drop.ts` | Where a canvas drag would land for a pointer position (spec drag-reorder-canvas, "Hit zones and thresholds"): the deepest node under the pointer outside the dragged nodes, a leaf's halves, a container's edge bands and, between them (and on the page root's background), inside it at the slot of the pointer (drag-drop-inside), the escape ladder over a leaf's ancestors (the innermost first; never narrower than `drop.escapeBandFloor`), as a parent and an index among its children without the dragged nodes; over the dragged nodes' own subtree, a refused proposal on the deepest of them, which `element.moveTo` refuses on release (drag-drop-inside, Problems in Pager 1).
